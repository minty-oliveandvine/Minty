Stripe Elements, in page, shared by: * the lapsed-trial restart screen ("Use a different card" / "Add a card"), and * the trial decision modal, when the payer has no card at all. SHARED ON PURPOSE. The decision modal used to hand that second case to Stripe — ``addPaymentMethod`` posted for a hosted URL and navigated away, so a payer answering "keep my trial" lost the page mid-decision and had to re-make it on their return. Bringing it in page meant an Elements form here anyway, and a second integration would be a second place for the mandate wording, the ``terms.card`` suppression and the mount ordering to drift apart. Exposes exactly one global, ``window.openCardCapture()``, resolving: { saved: true, paymentMethod: 'pm_...' } saved and made the default { saved: false } cancelled, or it could not be saved THE CALLER decides what happens next — the restart screen reloads to re-render its server-rendered card list, the decision modal carries straight on to record consent. Baking either in here would make the component useless to the other. Rendered whenever the viewer may manage this entity's subscription, not only when something has lapsed: the decision modal needs it on an ordinary page. #}
