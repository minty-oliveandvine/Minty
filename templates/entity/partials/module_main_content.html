{# THE SWITCH between the ordinary module page and the lapsed-trial restart screen. Branched here, once, so the two parent templates (settings_module.html and its bills-UI twin) each carry a single include and cannot drift apart. THE ORDINARY PAGE ALWAYS RENDERS. The restart screen sits on top of it as a dialog rather than replacing it — a payer who wants to read what they had, or reach another control, can dismiss it and do so. DISMISSED IS NOT ANSWERED. Nothing is remembered: no storage key, no server flag, no cookie. Closing it hides it for this view of the page and it returns on the next load, every time, until the payer actually restarts or cancels. That is the whole design — it does not block, and it does not go away either. Three states, from ``modules.build_consent_takeover``: * takeover — nothing live is left. * panel — something lapsed but another module is still trialing. * falsy — nothing lapsed, or an entity that still pays for something. Nothing extra. BOTH modes are the same dialog. They differ only in what it says: the panel wording scopes itself to the module that went dark, so a payer whose other trial is running fine does not read it as a threat to everything. Both dismiss, because both leave a page underneath that is worth reaching — in panel mode a live trial with its own controls, in takeover mode the record of what was there. ``can_act`` gates the form everywhere: a co-admin gets the notice naming the payer and never a control ``require_subscription_payer`` would refuse. #} {# The entrance every dialog on this page uses, in one place rather than four. Written as plain CSS, not Tailwind: this page compiles Tailwind IN THE BROWSER from a CDN build, and keyframes are exactly the kind of thing that build has no way to know it needs. A rule here is a rule, whatever the CDN decides to generate. Matched to onboarding's ``.buynow-sheet`` and the payer portal's dialogs: a 150ms fade on the scrim and a 180ms fade-and-rise on the panel. TRANSLATE ONLY — NEVER SCALE. ``transform: scale()`` changes what getBoundingClientRect reports, and Stripe measures the box it mounts into. A panel still scaling at 0.98 when the Elements iframe mounts lays the card form out to a width the dialog does not have. A translate moves the box without resizing it, so the same entrance is safe on the capture dialog. ENTER ONLY. These dialogs are shown by removing ``hidden``, which is what restarts the animation — going from display:none to displayed runs it again, so no JS is involved and reopening replays it. Animating the CLOSE would mean holding a dismissed dialog on screen until its animation finished, and a dialog that fails to finish animating is one that never goes away. #}
