{# Subscription decision modal — the one place the shape of the subscription is chosen. TWO variants of the same list, picked by what the entity actually has: * trial — "We're glad with your decision!". Only live modules are listed, ticked. Continue asks for whatever the kept trials still need (a card, or billing consent) so they convert instead of expiring. * paid — "Change your modules". Adds the modules the entity does NOT have, so the list is add-or-remove, and Save changes applies both directions. What each row does when it is ticked / unticked is decided by data-keep-state: trial ticked → needs card or consent CANNOT BE UNTICKED (box is disabled) paid ticked → nothing (already on) unticked → prorated cancel, priced+confirmed available ticked → subscribe (charged) unticked → nothing winding ticked → renew unticked → nothing CANCELLING A FREE TRIAL IS NOT OFFERED IN THE UI. It was this modal's untick, and nothing else — the module cards never carried it — so removing the untick removes the only route to it. The server-side cancellation is untouched (``entity_settings_module_cancel`` still accepts a trialing module, and the scheduler and support tooling still reach it); a trial cancelled by any of those still shows up here as a winding row, and re-ticking it is how it is kept. z-[95] — deliberately BELOW the blocking loader (100) and the billing confirm dialog (110), because it stays open while the decision is applied: the loader has to cover it, and the confirmations it raises have to sit on top of it. #} {# The trial's end date — from ANY trialing module, cancelled or not: a cancelled trial still runs to that date, and that is the date its copy has to name. #} {% set trial_end = ((module_cards or []) | selectattr('subscription_status', 'equalto', 'trialing') | map(attribute='period_end_long') | select | first) %}
