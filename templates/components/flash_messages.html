{# Canonical flash + client-notification toast. ONE toast for the whole app. Every page includes this partial (base/layout.html and the standalone templates); no page keeps its own toast markup or toast function any more. The look is the house toast shared with minty-web (components/ui/Toast.tsx is the reference): a white card, a bold type label (Success / Error / Warning / Information), the message in grey and a close button, stacked at the top-right. No per-type colour or icon by decision. It drains `get_flashed_messages()` at the bottom so EVERY page that includes this partial consumes the session flash queue on load. That consumption is the whole point: without it, a flash queued by a redirect (session expired, "entity not found", read-only write, CSRF) survives in the session and pops up later on some unrelated page - the "stale toast" bug. Client code raises a toast with showFlashMessages(message, type, durationMs) or one of the aliases below (showToast / showSuccessToast / showErrorToast / ...). Every message is set with textContent, never innerHTML. #}
